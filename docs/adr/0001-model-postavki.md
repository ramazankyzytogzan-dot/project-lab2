\# ADR-001: Выбор модели поставки и организации рабочего пространства CafeFlow



\* \*\*Статус:\*\* Принято

\* \*\*Дата:\*\* 16.09.2026

\* \*\*Авторы:\*\* Команда разработки CafeFlow



\## Контекст

Для реализации ИС «CafeFlow» необходимо определить подход к управлению задачами, хранению документации и автоматизации процессов разработки.



\## Рассматриваемые варианты

1\. \*\*GitHub Ecosystem:\*\* GitHub Projects + GitHub Wiki + GitHub Actions (монолитная среда).

2\. \*\*Сторонние сервисы:\*\* Jira + Confluence + GitLab CI/CD (распределенная среда).



\## Решение

Использовать \*\*GitHub Ecosystem\*\*, так как исходный код, задачи, Вики-документация и CI/CD хранятся в одном месте, что ускоряет командное взаимодействие.



\## Последствия

\* \*\*Плюсы:\*\* Единственная точка входа, единый доступ для преподавателя и команды, бесплатные инструменты.

\* \*\*Минусы:\*\* Меньше гибких настроек по сравнению с Jira, но для рамок лабораторной работы их более чем достаточно.
